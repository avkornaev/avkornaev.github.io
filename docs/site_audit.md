## Proposed Publication Schema

Use `bibliography/publications.bib` as the factual source. Use `_data/publications.yml` as a presentation/enrichment layer for reusable exports, filters, CV snippets, and artifact links.

Required publication fields:

- `id`: stable identifier; prefer DOI, otherwise BibTeX key or checked external record.
- `bibtex_key`: key in `bibliography/publications.bib`.
- `title`, `authors`, `year`, `type`, `category`, `venue`.
- `doi`, `url`, and `links.paper/code/project/slides/dataset`.
- `metadata_sources`, `metadata_status`, and `todo` for review workflow.

Recommended optional fields for the next pass:

- `selected`, `research_area`, `abstract`, `contribution`, `artifacts`, `image_prompt`, and `cv_group`.
- Keep these optional until the underlying facts are verified.

## Proposed Course Schema

Use `_data/courses.yml` as the reusable source for Teaching, CV, reports, and application materials.

Required course fields:

- `id`, `title`, `short_title`, `level`, `role`, `years`, `term`, `institution`, `status`.
- `summary`, `topics`, `tools`, `links`, `weeks`, and `todo`.

Week records should include:

- `week`, `title`, `topics`, `labs`, and `status`.
- Lab records should include `title` and repository-relative `path` or public URL.
